# ebrowse — Contributor Guide

You are working on `ebrowse`, a token-efficient browser-control CLI for AI agents:
pages render as sectioned outlines, agents expand only what they need, and every
action answers with a diff of what changed. Read
[docs/architecture.md](docs/architecture.md) and
[docs/output-contracts.md](docs/output-contracts.md) before writing code.

## Principles digest (binding — full text in docs/architecture.md)

1. Determinism first; the LLM sidecar only produces labels/captions, never anything
   load-bearing. Every feature works with no LLM configured.
2. Token economy of all default output; formats are golden-tested.
3. `core/` is pure: DomSnapshot JSON in → PageMem/Diff/text out. Playwright calls are
   allowed ONLY in `core/snapshot.py` (evaluate wrapper), `core/locate.py`, and
   screenshot clipping. Never per-element round trips.
4. `model.py` and the output formats are FROZEN. Add optional fields; never repurpose.
   Renderer changes require updating `tests/golden/` + docs/output-contracts.md together.
5. No site-specific heuristics, ever.
6. Defaults need zero flags; complexity is opt-in.
7. Every change ends with a working tool (`make lint typecheck test` green, prior verbs intact).
8. Errors name the recovery action ("run 'ebrowse outline'").

## Layout & commands

- `src/ebrowse/` — package (module map in docs/architecture.md).
- `tests/fixtures/pages/` — fixture site; `list/table/huge.html` are generated by
  `python tests/fixtures/generate.py` (edit the generator, not the output).
- `make setup` — uv sync + playwright chromium.
- `make test` — pure tests only (fast, no browser).
- `make test-browser` — includes `browser`/`e2e` marks. `make lint` / `make fmt` /
  `make typecheck` (pyright, basic mode). CI (`.github/workflows/ci.yml`) runs
  lint+typecheck+pure tests and a separate browser-test job on every push/PR.
- Dev harness (no daemon): `uv run python -m ebrowse.dev <url> outline`.

## Real-site testing

Fixture tests prove correctness; real sites prove the heuristics. For manual/dev
testing use sites from the Online-Mind2Web dataset
(`/home/jayoo/code/pytorch_docker/Web_Nav/datasets/Online-Mind2Web/Online-Mind2Web/Online_Mind2Web_(updated).json`)
— e.g. bestbuy.com, traderjoes.com, recreation.gov, drugs.com. They are permissive
about automation and safe to interact with (read-only; don't order/register).
Validate on ≥2 real sites before calling a feature done; note edge cases as code
comments where handled.

## Documentation & process conventions

- **docs/** holds the detailed references: [architecture](docs/architecture.md),
  [output contracts](docs/output-contracts.md) (frozen formats + golden-test anchor),
  [configuration](docs/configuration.md).
- **Non-obvious decisions become ADRs** in [docs/adr/](docs/adr/README.md) — write one
  when a choice would surprise a future reader or got reversed after real-world
  testing. Keep them short (Status/Context/Decision/Consequences).
- **Planned/deferred work lives in GitHub issues**, not in tracking docs. Completed
  work is recorded in [CHANGELOG.md](CHANGELOG.md) (Keep-a-Changelog style; update the
  Unreleased section in the same PR as the change; releases are git tags).
- **User-facing docs**: [README.md](README.md) (install/quickstart/verb reference —
  must only document what works) and [SKILL.md](SKILL.md) (host-agent operating guide —
  THE doc agents read to *drive* the tool). Update them in the same commit as behavior
  changes.
- `agent-browser/` is a vendored read-only reference checkout — never modify it.
